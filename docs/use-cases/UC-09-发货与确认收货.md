# UC-09 发货与确认收货

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-09 |
| 用例名称 | 发货与确认收货 |
| 参与者 | 农户（发货）、消费者（确认收货） |
| 所属业务域 | 交易域 |
| 负责人 | 李×× |
| 对应接口 | `GET /api/orders?scope=sales`、`POST /api/orders/{id}/ship`、`POST /api/orders/{id}/receive` |
| 关联需求 | 表 2-3「交易管理 / 履约」，优先级 S；UC-10 的前置 |

## 前置条件

1. 订单状态为 `paid`（发货）或 `shipped`（确认收货）；
2. 发货人须为订单供货产地的所有者；确认收货人须为订单买家。

## 后置条件

1. 发货：订单状态 `paid → shipped`，写入 `express_no` 与 `shipped_at`；
2. 收货：订单状态 `shipped → received`，写入 `received_at`，订单进入可评价状态。

## 基本流程

1. 农户在「订单中心 → 我卖出的」看到状态为「已支付」的订单；
2. 农户点击「发货」，填写物流单号；
3. 系统校验产地归属与状态机，写入单号与发货时间；
4. 消费者在「我买到的」看到「已发货」与物流单号；
5. 消费者收到货后点击「确认收货」；
6. 系统将状态置为「已收货」，页面出现「评价」按钮。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 3a | 非本产地农户发货 | 403 `40301`「只能管理本产地的商品与订单」 |
| 3b | 订单未支付即发货 | 422 `42201`「当前订单状态为「待支付」，不可发货」 |
| 3c | 重复发货 | 422（`shipped` 已不是 `paid`） |
| 5a | 未发货即确认收货 | 422「当前订单状态为「已支付」，不可确认收货」 |
| 5b | 非买家确认收货 | 403「只能确认本人的订单」 |

## 业务规则

- **BR-26** 订单状态机单向流转，禁止回退与跳步：

```
pending ──支付成功──▶ paid ──发货──▶ shipped ──确认收货──▶ received
   │
   └──取消/超时──▶ cancelled
```

- **BR-27** 物流单号由农户手工填写（课程项目不接真实物流查询），长度 4~64，仅发货时写一次；
- **BR-28** 平台运营可查看全部订单，但不代发货（避免责任边界模糊）；
- **BR-29** 确认收货后不可再取消订单，售后走线下流程（课程项目不做退款）。

## 权限矩阵

| 操作 | 消费者 | 农户（供货方） | 农户（非供货方） | 平台运营 |
|---|---|---|---|---|
| 查看订单 | 本人订单 | 本产地订单 | ✗ | 全部 |
| 支付 | 本人订单 | ✗ | ✗ | ✗ |
| 发货 | ✗ | ✓ | ✗ | ✗ |
| 确认收货 | 本人订单 | ✗ | ✗ | ✗ |
| 取消订单 | 本人 `pending` 订单 | ✗ | ✗ | ✓ |
