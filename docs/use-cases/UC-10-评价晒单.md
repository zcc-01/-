# UC-10 评价晒单

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-10 |
| 用例名称 | 评价晒单 |
| 参与者 | 消费者（主要） |
| 所属业务域 | 交易域 |
| 负责人 | 李×× |
| 对应接口 | `POST /api/orders/{id}/reviews`、`GET /api/products/{id}/reviews` |
| 关联需求 | 表 2-3「交易管理 / 评价」，优先级 C；扩展关系：UC-10 扩展 UC-09，仅收货后可评价 |

## 前置条件

1. 订单状态为 `received`（已确认收货）；
2. 被评商品必须在该订单的明细中；
3. 同一订单中的同一商品尚未评价过。

## 后置条件

1. `review` 表新增一行，记录评分、内容、关联批次与评价人；
2. 商品详情的评分均值与评价数即时更新；
3. 评价内容中不出现买家手机号、全名等可识别身份的信息。

## 基本流程

1. 消费者在「我买到的」中找到已收货订单，点击商品行的「评价」；
2. 页面展开评价表单：评分（1~5 星）与文字内容（≤ 500 字）；
3. 消费者提交；
4. 系统校验订单状态、商品归属与唯一性；
5. 系统落库并返回评价结果；
6. 商品详情页在「买家评价」区展示：脱敏昵称、星级、时间、内容。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 4a | 订单未收货 | 422 `42201`「订单确认收货后才能评价」 |
| 4b | 商品不在该订单中 | 422「该商品不在本订单中」 |
| 4c | 重复评价 | 409 `40901`「该订单中的这个商品已评价，请勿重复提交」 |
| 4d | 评分越界 / 内容超长 | 422 `40001` 参数校验失败 |
| 5a | 并发重复提交 | `(order_id, product_id)` 唯一索引兜底，捕获 `IntegrityError` 后返回 409 |

## 业务规则

- **BR-30** 只有买家本人可评价，且必须已确认收货；
- **BR-31** 一单一商品仅一条评价，不做修改与追评（课程范围）；
- **BR-32** 展示时买家名脱敏为「姓 + **」，与溯源域操作人脱敏同一口径（BR-13）；
- **BR-33** 评价支持关联批次：`review.batch_id` 复制自 `order_item.batch_id`，可用于「按批次看口碑」；
- **BR-34** 商品评分 = 该商品全部评价的算术平均，保留一位小数。

## 与溯源域的联动

评价表单不做「晒溯源截图」，但评价记录带 `batch_id`。后续若要做「溯源可信度与口碑相关性分析」，
直接 join `trace_event` 即可，不需要改交易域表结构。
