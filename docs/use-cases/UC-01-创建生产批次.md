# UC-01 创建生产批次

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-01 |
| 用例名称 | 创建生产批次 |
| 参与者 | 农户（主要） |
| 所属业务域 | 溯源链域 |
| 负责人 | 张×× |
| 对应接口 | `POST /api/batches` |
| 关联需求 | 表 2-3「溯源管理 / 批次建档」，优先级 M |

## 前置条件

1. 农户已登录（持有有效 JWT），角色为 `farmer`；
2. 该农户名下已有通过审核的产地（`farm.owner_id = 当前用户`）；
3. 该地块在当前农事周期内尚未建立同品种、同采收日期的批次。

## 后置条件

1. 新增一条 `batch` 记录，状态为 `draft`，生成对外批次号 `PC-YYYYMMDD-XXXX`；
2. 同事务内写入一条 `seq_no = 1` 的创世溯源记录（`stage = production`），
   `prev_hash = SHA-256("GENESIS"|batch_id)`，`curr_hash` 按统一口径计算；
3. `batch.event_count = 1`、`batch.last_event_hash = curr_hash`，链尾锚点就位；
4. 接口返回批次详情，`code = 0`。

## 基本流程

1. 农户在「批次建档」页填写品种、地块编号、播种日期、采收日期、预计产量；
2. 前端提交 `farm_id` 与上述字段到 `POST /api/batches`；
3. 系统校验登录态与角色，解析 `farm_id` 对应产地；
4. 系统校验产地归属、日期合法性与批次唯一性；
5. 系统生成 `batch_id`（雪花字符串）与 `batch_no`，写入 `batch`；
6. 系统计算创世摘要并写入首条 `trace_event`，同步更新批次链尾锚点；
7. 系统提交事务并返回批次详情。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 3a | 未携带令牌或令牌过期 | 401，`code = 40101`「未登录或登录已过期」 |
| 3b | 角色不是农户 | 403，`code = 40301` |
| 4a | `farm_id` 不存在 | 404，`code = 40401`「产地不存在，请先完成产地入驻」 |
| 4b | 产地不属于当前农户 | 403，「只能为本人产地建档」 |
| 4c | 采收日期早于播种日期 | 422，`code = 40001`，返回字段级错误 |
| 4d | 同产地 + 地块 + 品种 + 采收日期已存在 | 409，`code = 40901`「请勿重复建档」 |
| 6a | 落库失败（唯一约束冲突等） | 事务整体回滚，不会出现「有批次无创世记录」的半成品数据 |

## 业务规则

- **BR-01** 批次是溯源的默认粒度，其唯一性由业务校验 + 数据库唯一索引 `(farm_id, plot_no, crop_name, harvest_date)` 双重保证；
- **BR-02** 创世记录的 `prev_hash` 使用固定盐值与 `batch_id` 的摘要，**不使用随机数**，保证同一批次的链基准可重现、可复核；
- **BR-03** 建档与创世记录必须在同一事务内完成，否则视为失败；
- **BR-04** 建档时批次状态固定为 `draft`，状态只能按 `draft → growing → harvested → qualified → closed` 单向流转，禁止回退。

## 验收用例

| 用例 | 预期 |
|---|---|
| 正常建档 | 200，`event_count = 1`，链校验通过 |
| 重复提交同一批次 | 409 |
| 采收日期早于播种日期 | 422 |
| 消费者调用 | 403 |
| 匿名调用 | 401 |
| 用他人 `farm_id` 建档 | 403 |
