# UC-06 商品上架管理

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-06 |
| 用例名称 | 商品上架管理 |
| 参与者 | 农户（主要）、平台运营（辅助，只读监管） |
| 所属业务域 | 交易域 |
| 负责人 | 李×× |
| 对应接口 | `POST /api/products`、`PATCH /api/products/{id}`、`PATCH /api/products/{id}/status`、`GET /api/products?mine=true` |
| 关联需求 | 表 2-3「交易管理 / 商品管理」，优先级 M |

## 前置条件

1. 农户已登录，且在 `farm` 表中拥有至少一个产地；
2. 若关联生产批次，该批次的 `farm_id` 必须与商品所属产地一致。

## 后置条件

1. `product` 表新增一行，`product_no` 为 `SP-YYYYMMDD-XXXX`，初始状态 `on_shelf`；
2. 商品出现在 `GET /api/products` 的检索结果中（`on_shelf` 才会对外可见）；
3. 下架后不再出现在消费者列表，但本产地农户在 `mine=true` 时仍可见，便于重新上架。

## 基本流程

1. 农户进入「商品管理」，点击「上架商品」；
2. 填写产地、关联批次（可选）、标题、品种、规格、单位、价格、库存、认证标识、描述；
3. 系统校验产地归属与批次归属；
4. 系统校验 `(产地, 批次, 标题, 规格)` 是否重复；
5. 系统生成商品编号并落库，状态置为在售；
6. 页面展示新商品与其对外链接 `/shop/{product_id}`。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 3a | 产地不属于本人 | 403 `40301`「只能管理本产地的商品与订单」 |
| 3b | 关联批次属于其他产地 | 403「只能关联本产地的生产批次」 |
| 4a | 同批次同规格已存在 | 409 `40901`「同批次同规格的商品已存在，请直接修改价格或库存」 |
| 2a | 价格 ≤ 0 或库存 < 0 | 422 `40001` 参数校验失败（Pydantic 字段级错误） |

## 业务规则

- **BR-14** 商品必须先绑定产地；产地认证状态由用户与运营域维护，通过后回填 `cert_badge`，交易域只读；
- **BR-15** 一个商品行就是一个 SKU（产地 + 批次 + 规格），多规格请建多行，不做 SKU 子表；
- **BR-16** 已产生的历史订单不受商品改价、改名、下架影响（`order_item` 存快照）；
- **BR-17** 下架不等于删除：`product` 不做物理删除，避免历史订单与评价出现悬空外键。

## 状态说明

商品只有两个状态，不做中间态：

```
off_shelf  ──上架──▶  on_shelf
    ▲                    │
    └──────下架──────────┘
```

库存为 0 仍可保持在售状态（页面显示「暂时无货」），与「下架」是两个不同语义：
前者是卖完了，后者是主动停售。
