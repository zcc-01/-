# UC-07 检索与筛选商品

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-07 |
| 用例名称 | 检索与筛选商品 |
| 参与者 | 消费者（主要）、游客（匿名，未登录亦可浏览） |
| 所属业务域 | 交易域 |
| 负责人 | 李×× |
| 对应接口 | `GET /api/products`、`GET /api/products/{id}`、`GET /api/products/{id}/reviews`、`POST /api/cart/quote` |
| 关联需求 | 表 2-3「交易管理 / 商品检索」，优先级 M |

## 前置条件

1. 平台存在状态为 `on_shelf` 的商品；
2. 无需登录（与 UC-04 扫码查询同一口径：浏览不设门槛）。

## 后置条件

1. 返回符合筛选条件的商品分页列表，含产地、认证标识、评分与是否可买；
2. 商品详情页返回关联的生产批次摘要，可继续跳转溯源时间轴；
3. 不产生任何写操作（试算也不写库）。

## 基本流程

1. 消费者进入 `/shop`，页面自动加载第一页商品；
2. 消费者输入关键词、价格区间，勾选「仅看产地认证 / 仅看有货」，选择排序方式；
3. 系统按条件查询并返回 `items` 与 `total`；
4. 消费者点击商品进入 `/shop/{product_id}`；
5. 系统返回商品详情：产地名称与位置、批次号 / 地块 / 采收日期 / 链上环节数、评分与评价数；
6. 消费者选择数量并加入购物车，前端调用 `POST /api/cart/quote` 试算金额与运费。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 3a | 无匹配结果 | 200，`items = []`，页面提示「没有匹配的商品，试试调整筛选条件」 |
| 3b | 价格区间传反 | 服务端自动交换 `min_price` / `max_price`，不报错 |
| 4a | 商品已下架 | 404 `40401`「商品已下架」（本产地农户访问除外） |
| 6a | 试算时商品已下架 | 200，`available = false`，`reason` 说明「xx 已下架」，前端标黄提示 |
| 6b | 试算时库存不足 | 200，`available = false`，`reason` 说明「库存不足（仅剩 n 件）」 |

## 业务规则

- **BR-18** 默认只返回 `on_shelf` 商品；农户传 `mine=true` 时才包含自己的下架商品；
- **BR-19** 排序字段白名单：`newest` / `sales_desc` / `price_asc` / `price_desc`，其他值回落到 `newest`，避免拼接注入；
- **BR-20** 试算结果不作为库存裁决，只用于结算页提示；最终以 UC-08 的条件更新为准；
- **BR-21** 运费规则：单笔（单产地）商品金额满 99 元免运费，否则 8 元；跨产地按产地分别计算。

## 性能考虑

列表接口一次查询商品、一次批量查产地（`farm_map`）、一次聚合评分（`rating_map`），
避免 N+1：20 条商品只产生 3 条 SQL。关键词使用前缀 + 包含匹配（`LIKE %kw%`），
课程量级下 1 万商品实测 < 20 ms；数据量再大时改用 MySQL 全文索引或独立搜索引擎。
