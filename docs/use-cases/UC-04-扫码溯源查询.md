# UC-04 扫码溯源查询

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-04 |
| 用例名称 | 扫码溯源查询 |
| 参与者 | 消费者（主要）、二维码扫描器（辅助） |
| 所属业务域 | 溯源链域 |
| 负责人 | 张×× |
| 对应接口 | `GET /api/trace/{code}`（JSON）、`GET /trace/{code}`（页面） |
| 关联需求 | 表 2-3「溯源管理 / 扫码溯源查询」，优先级 M；包含 UC-05 的校验步骤 |

## 前置条件

1. 码值已在系统中生成，且状态为 `active`；
2. 无需登录（BR-01），未注册用户亦可查询。

## 后置条件

1. 返回产地信息、批次信息、按 `seq_no` 升序的环节时间轴与链校验结论；
2. 写入一条扫码日志（码值、时间、地域、设备、IP），日志失败不影响查询结果；
3. 若校验发现异常，页面顶部展示告警条，同时仍完整展示已存在的记录。

## 基本流程

1. 消费者扫描包装二维码，浏览器打开 `/trace/{code}`；
2. 系统解析码值并识别码类型（批次码 / 单品码）；
3. 系统按码值查询溯源单元与归属产地；
4. 系统按环节顺序组装时间轴，并调用哈希链校验服务；
5. 系统返回产地信息、环节记录、检测结论与校验结论；
6. 系统写入扫码日志；
7. 页面渲染时间轴、链校验徽标与最近校验时间。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 3a | 码值不存在 | 404，`code = 40401`「未查询到该产品信息，请核对包装上的溯源码」 |
| 3b | 码值已作废 | 410，`code = 42202`「该溯源码已作废」 |
| 4a | 校验发现断链 | 200 正常展示记录，`chain.ok = false`，页面顶部黄色告警条「该产品溯源信息存在异常，已提交平台复核」 |
| 4b | 校验服务异常 | 降级为 `reason = verify_error`，仍返回记录，不整页 500 |
| 6a | 日志写入失败 | 吞掉异常并回滚日志事务，查询结果照常返回（后续可换消息队列补写） |

## 业务规则

- **BR-01** 未注册用户亦可查询，不要求登录；
- **BR-02** 检测报告仅展示结论与报告编号，不展示原始附件；
- **BR-03** 单品码查询时，若该单品无独立环节记录，则回退展示所属批次记录并标注「批次级记录」（响应 `scope = item`、`scope_note` 说明）；
- **BR-13** 操作人姓名必须脱敏（保留姓氏，其余替换为 `*`）。

## 验收用例

| 用例 | 预期 |
|---|---|
| 匿名扫码有效码 | 200，`chain.ok = true`，5 条记录 |
| 扫码后查日志 | `scan_log` 新增一条，地域与设备正确 |
| 扫不存在的码 | 404 |
| 扫已作废的码 | 410 |
| 数据被篡改后扫码 | 200，页面出现告警条，记录仍展示 |
