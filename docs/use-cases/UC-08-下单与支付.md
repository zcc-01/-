# UC-08 下单与支付

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-08 |
| 用例名称 | 下单与支付 |
| 参与者 | 消费者（主要）、支付网关（辅助，本项目为模拟网关） |
| 所属业务域 | 交易域 |
| 负责人 | 李×× |
| 对应接口 | `POST /api/cart/quote`、`POST /api/orders`、`POST /api/orders/{id}/pay`、`POST /api/orders/{id}/cancel`、`POST /api/orders/admin/sweep-expired` |
| 关联需求 | 表 2-3「交易管理 / 下单支付」，优先级 M；报告 5.2.3 的核心实现 |

## 前置条件

1. 消费者已登录（角色必须为 `consumer`）；
2. 购物车中存在可售商品，且库存充足。

## 后置条件

1. 生成一笔或多笔订单（按产地拆单），状态 `pending`，同时按条件更新扣减库存；
2. 支付成功后订单状态 `paid`，生成唯一的成功支付流水，并累加商品销量；
3. 支付失败累计 3 次、或超时 30 分钟未支付，订单转 `cancelled` 且库存原路释放。

## 基本流程

1. 消费者在购物车页确认商品与数量，填写收货人、手机号、详细地址；
2. 前端调用 `POST /api/cart/quote` 展示商品金额、运费与应付合计；
3. 消费者提交订单，前端只上送 `items[{product_id, quantity}]`、地址与备注；
4. 服务端按 `farm_id` 分组，逐件执行条件更新扣减库存；
5. 服务端按库中当前价重算金额与运费，写入 `orders` 与 `order_item`（含商品快照）；
6. 事务提交，返回订单号与应付金额；
7. 消费者点击「立即支付」，服务端在事务外调用模拟网关 `pay(order_no, amount)`；
8. 网关返回成功，服务端用短事务更新订单为 `paid` 并写入 `payment` 流水；
9. 页面展示支付成功与交易号。

## 异常流程

| 编号 | 触发条件 | 系统响应 |
|---|---|---|
| 4a | 商品已下架 | 422 `42201`「「xx」已下架，请调整数量后重试」，整笔事务回滚 |
| 4b | 库存不足 | 422 `42201`「「xx」库存不足（仅剩 n 件）」，`data` 带 `product_id` 与剩余库存，整笔回滚 |
| 4c | 同一商品行重复提交 | 服务端按 `product_id` 合并数量，超过单品上限 99 件返回 422 |
| 7a | 网关超时 | 订单保持 `pending`，页面提供「重新支付」入口；30 分钟后自动取消并释放库存 |
| 7b | 网关拒付 | 422 `42201`「支付失败：原因」，失败原因落库并累加 `attempt_count` |
| 7c | 失败累计 3 次 | 自动取消订单、释放库存，此后支付返回「支付重试次数已达上限」 |
| 8a | 并发重复点击支付 | `payment.order_id` 唯一索引拦下第二条流水，回滚后按幂等返回既有流水 |

## 业务规则

- **BR-04** 同一订单仅允许一条成功支付流水（数据库唯一索引落地）；
- **BR-05** 库存扣减采用条件更新，`affected_rows = 0` 即判定失败并回滚整个下单事务；
- **BR-06** 订单取消后库存原路释放，不允许人工直接改库存；
- **BR-22** 订单金额由服务端按商品当前价重算，客户端传入的 `price` / `total_amount` 一律忽略；
- **BR-23** 一单一产地，跨产地购物车自动拆单，同一事务内全成功或全回滚；
- **BR-24** 运费满 99 元免、否则 8 元，按产地分别计算；
- **BR-25** 支付调用在数据库事务之外执行，避免外部超时长时间占用连接；
- **BR-35** 商品若绑定生产批次，其溯源码全部作废时禁止下单（跨域契约，交易域只读 `trace_code`）；批次尚未赋码不拦截。

## 事务边界（实现要点）

```
[事务 1] 校验 → 条件更新扣库存 → 写 orders/order_item → COMMIT
          ↓
[事务外] gateway.pay(order_no, amount)     ← 不允许出现任何 Session 写操作
          ↓
[事务 2] 更新 order.status=paid → 写/更新 payment → 累加 sales → COMMIT
```

把支付放在事务外是报告 5.2.3 记录的人工修改点：AI 最初把网关调用写在下单事务里，
网关响应慢时数据库连接被长时间占用，压测下连接池迅速耗尽。

## 并发正确性

- 超卖：20 线程抢 5 件库存，条件更新保证最终售出 ≤ 5 且 `stock == 初始值 - 售出数量`；
- 重复支付：两请求同时通过状态检查，唯一索引使其中一条 `IntegrityError`，捕获后幂等返回。
