# 接口文档（溯源链域）

- Base URL：`http://127.0.0.1:8000`
- 在线调试：`/docs`（Swagger UI）、`/redoc`
- 统一响应：`{"code": 0, "message": "ok", "data": ...}`
- 鉴权：`Authorization: Bearer <access_token>`，令牌有效期默认 120 分钟

## 错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40001 | 422 | 参数校验失败（`data` 为字段级错误列表） |
| 40101 | 401 | 未登录 / 令牌过期 |
| 40301 | 403 | 权限不足 |
| 40401 | 404 | 资源不存在 |
| 40901 | 409 | 资源冲突（重复建档、赋码冲突） |
| 42201 | 422 | 业务规则不满足（状态机、赋码前置条件） |
| 42202 | 410 | 溯源码已作废 |
| 50001 | 500 | 服务内部错误 |
| 50002 | 503 | 哈希链并发写入冲突（重试后仍失败） |

## 1. 登录

`POST /api/auth/login`

```json
{"username": "farmer01", "password": "Passw0rd!"}
```

响应 `data`：

```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "expires_in": 7200,
  "user": {"user_id": "USR...", "username": "farmer01", "display_name": "张建国", "role": "farmer"}
}
```

演示免密登录：`POST /api/auth/dev-login`，body `{"username": "farmer01"}`，仅在 `DEV_MODE=true` 时可用。

```bash
TOKEN=$(curl -s -X POST localhost:8000/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"farmer01","password":"Passw0rd!"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")
```

## 2. 创建生产批次（UC-01）

`POST /api/batches`　权限：农户

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| farm_id | string | 是 | 本人名下产地 |
| crop_name | string | 是 | 品种，1~64 字 |
| plot_no | string | 是 | 地块编号，1~32 字 |
| plant_date | date | 是 | `YYYY-MM-DD` |
| harvest_date | date | 是 | 不得早于播种日期 |
| expected_yield | number | 否 | 预计产量（kg），0~1000000 |

```bash
curl -X POST localhost:8000/api/batches -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"farm_id":"FRM...","crop_name":"临安山核桃","plot_no":"A-03",
       "plant_date":"2026-03-20","harvest_date":"2026-09-05","expected_yield":2600}'
```

响应 `data`：`batch_id`、`batch_no`、`status`（`draft`）、`event_count`（1）、`last_event_hash`。

错误：`409` 重复建档、`403` 非本人产地、`404` 产地不存在、`422` 日期非法。

## 3. 批次列表与详情

`GET /api/batches?status=harvested&page=1&size=20`　权限：农户/运营/监管

农户只能看到自己产地的批次；运营与监管可看全部。

`GET /api/batches/{batch_id}`　返回批次字段 + `farm` + `events[]` + `code_count`。

`PATCH /api/batches/{batch_id}/status`　权限：农户

```json
{"status": "harvested"}
```

允许流转：`draft → growing|harvested`、`growing → harvested`、`harvested → qualified`、`qualified → closed`；
回退或跳步返回 `422`。

## 4. 录入溯源环节（UC-02）

`POST /api/batches/{batch_id}/events`　权限：农户

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| stage | enum | 是 | `production/processing/quality/logistics/sales` |
| occurred_at | datetime | 否 | 缺省为当前时间；统一按秒精度入链 |
| location | string | 否 | ≤128 字 |
| detail | object | 否 | 明细，序列化后 ≤4000 字符 |

```bash
curl -X POST localhost:8000/api/batches/$BID/events -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"stage":"quality","occurred_at":"2026-09-12T14:20:00",
       "location":"临安区农检中心","detail":{"report_no":"ZJ-2026-0912","conclusion":"合格"}}'
```

响应：

```json
{"code": 0, "message": "环节记录已上链",
 "data": {"event": {"seq_no": 2, "curr_hash": "…", "prev_hash": "…"}, "warning": null}}
```

`warning` 非空表示环节时间早于上一条记录（UC-14 扩展点），记录仍会上链。

`GET /api/batches/{batch_id}/events` 返回按 `seq_no` 升序的数组。

## 5. 赋码与二维码导出（UC-03）

`POST /api/batches/{batch_id}/codes`　权限：农户

```json
{"code_type": "item", "count": 5}
```

- `count` 取值 1~5000；
- 码值规则：`{batch_no}-ITM0001` / `{batch_no}-BOX0001`；
- 重复提交相同请求返回同一组码（幂等）。

`GET /api/batches/{batch_id}/codes?code_type=item&limit=100`

`GET /api/batches/{batch_id}/qrcodes.zip?code_type=item&limit=5000`　返回 `application/zip`，
内含 `*.png`、`manifest.csv`（码值、类型、扫码链接）、`README.txt`。

作废：`POST /api/codes/{code_value}/revoke`，body `{"reason": "包装破损"}`。

## 6. 扫码溯源（UC-04，公开）

`GET /api/trace/{code_value}?province=浙江省&city=杭州市`

无需令牌。响应结构见 `docs/use-cases/UC-04-扫码溯源查询.md`。

要点：

- `chain.ok=false` 时仍返回全部记录，同时 `warning` 给出提示；
- `scope=item` 且 `scope_note` 说明「批次级记录」；
- 操作人姓名脱敏为「张**」；
- 每次查询写入 `scan_log`。

页面地址：`GET /trace/{code_value}`，返回 HTML 时间轴页（移动端 375px 无横向滚动）。

## 7. 链完整性校验（UC-05）

`GET /api/batches/{batch_id}/verify`　权限：运营/监管

```json
{"batch_id": "BAT...", "ok": false, "total": 2, "expected_total": 3,
 "broken_at": 2, "reason": "content_tampered", "broken_event_id": "EVT...",
 "message": "第 2 条记录校验失败：记录内容与摘要不一致，疑似字段被篡改", "checked_at": "..."}
```

`reason` 取值：`content_tampered`、`prev_hash_mismatch`、`seq_gap`、`count_mismatch`、
`tail_truncated`、`verify_error`。

## 8. 扫码日志

`GET /api/batches/{batch_id}/scans?limit=20`　权限：运营/监管

返回最近扫码记录：码值、时间、省市、设备类型。

## 10. 通用约定

- 时间字段：接口出入参使用 `YYYY-MM-DDTHH:MM:SS`（本地无时区表示），内部统一按 UTC 秒精度参与哈希；
- 分页响应：`{"items": [...], "total": 44, "page": 1, "size": 20}`；
- 每个响应带 `X-Request-ID`，排查问题请提供该值。
