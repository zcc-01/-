# 交易域文档与本仓库实现的映射

本目录下的三份文档（`交易域-设计与任务.md`、`接口文档-交易域.md`、`数据库设计-交易域.md`）
与 `docs/use-cases/UC-06～UC-10` 来自组员分支 `feat/trade`，**保留了原始设计表述**，
用于说明交易域的需求来源与设计推演。

本仓库最终运行的是同域的另一套实现（见 `docs/分支整合说明.md` §9），
两者在**业务规则层面一致、字段命名层面不同**。阅读代码时按下表换算，避免对不上。

## 1. 数据模型映射

| 组员文档字段 | 本仓库字段 | 说明 |
|---|---|---|
| `product_no`（商品编号） | `product_id`（雪花 ID） | 主键统一用 32 位字符串雪花，避免三域并行撞号 |
| `title` | `name` | 商品标题 |
| `crop_name` + `spec` | `category` + `unit` | 类目用于筛选，单位用于计价展示；品种与规格写入 `description` |
| `price`（`DECIMAL(10,2)`） | `price_cents`（`INT`） | 金额统一以「分」存储，规避浮点累加误差；对外仍返回 `price` 元 |
| `sales` | `sales_count` | 销量 |
| `status='on_shelf' / 'off_shelf'` | `status='on_sale' / 'off_shelf'` | 在售状态取值不同，语义一致 |
| `cert_badge`（字符串标识） | `certified`（0/1） | 本仓库用布尔位，认证通过时由运营域统一置 1 |
| `batch_id`（可空） | `batch_id`（非空） | 本仓库要求商品必须挂在已采收批次上，强化「交易与溯源同源」 |
| `order_no` / `total_amount` | `order_no` / `total_cents` | 订单号规则一致（`SO-YYYYMMDD-XXXX`） |

## 2. 接口映射

| 组员文档路径 | 本仓库路径 | 差异 |
|---|---|---|
| `GET /api/products?q=` | `GET /api/products?keyword=` | 关键词参数名 |
| `GET /api/products/{product_no}` | `GET /api/products/{product_id}` | 主键口径 |
| `POST /api/cart/items` | `POST /api/cart` | 加购路径 |
| `POST /api/orders`（body 含 `items`） | `POST /api/orders`（`cart_ids` 或 `product_id`） | 本仓库支持「购物车结算」与「立即购买」两种形态 |
| `POST /api/orders/{no}/pay` | `POST /api/orders/{id}/pay` | 一致（幂等 + 失败重试 3 次） |
| `POST /api/orders/{no}/ship` · `/receive` | 同名路径 | 一致 |
| `POST /api/orders/{no}/reviews` | 同名路径 | 一致（仅收货后可评） |

## 3. 已吸收的业务规则（两套实现一致的部分）

1. 同一订单仅允许一条成功支付流水（BR-04）——本仓库用「应用层先查 + 部分唯一索引」实现；
2. 库存扣减必须条件更新，扣不动即回滚（BR-05）；
3. 取消订单释放库存（BR-06）；
4. 订单金额由服务端按商品当前价重算，不信任客户端；
5. 评价前置条件：订单已收货且商品属于该订单。

## 4. 本仓库额外补充的跨域约束

`feat/trade` 分支独立开发时没有运营域，因此缺少以下约束，整合时补上：

| 约束 | 位置 | 原因 |
|---|---|---|
| 上架要求批次已采收（非 draft/growing/closed） | `ProductService._assert_sellable_batch` | 商品不能脱离溯源链存在 |
| 下单再次校验批次未结批/未封存 | `OrderService.create` | 售中可能被监管冻结或平台结批 |
| 认证通过后批量打认证标识 | `CertService.review` → `UPDATE product SET certified=1` | UC-12 步骤 7 |
