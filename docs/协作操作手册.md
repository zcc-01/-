# 协作操作手册（提交与改写代码）

面向：本小组 3 名成员
仓库：https://github.com/zcc-01/-

本项目按业务域纵向切分，每个人有独立的目录与分支，因此可以**并行直接提交**，
不需要互相等待。前提是遵守下文的「目录归属」与「分支归属」。

---

## 一、组长：开放写权限（一次性，约 2 分钟）

仓库在个人账号 `zcc-01` 名下，因此用「协作者」机制，不需要建组织。

1. 打开 https://github.com/zcc-01/-/settings/access
2. 点 **Add people**
3. 输入组员的 **GitHub 用户名**（或注册邮箱），回车
4. 权限选 **Write**（不要给 Admin，Write 已足够推代码、开 PR）
5. 点 **Add**

组员会收到 GitHub 邮件，**必须在邮件里点 Accept invitation**。
未接受邀请前，push 会返回 `403 Permission denied`。

查看是否已生效：同一页面会列出成员和角色，状态显示为 `Write`。
接受邀请后也可直接访问 https://github.com/zcc-01/- 确认能看到 Settings 之外的
Insights、Actions 等标签。

> 如果组员没有 GitHub 账号，先让他注册（免费），再回来加。
> 不建议为了省事共用你的账号，会导致提交记录无法区分成员，
> 而报告表 0-3 需要按人统计提交次数与代码行占比。

## 二、组员：首次配置（一次性，约 5 分钟）

### 1. 安装 Git

- Windows：https://git-scm.com/download/win ，一路默认即可（自带凭据管理器）
- macOS：终端执行 `xcode-select --install`

验证：`git --version` 有版本号输出。

### 2. 配置提交身份（务必用自己的名字和邮箱）

```bash
git config --global user.name "李××"
git config --global user.email "你的GitHub注册邮箱"
```

这一项决定了 GitHub 上提交记录显示谁。配错会导致你的提交算在别人头上，
直接影响报告里的个人贡献统计。

### 3. 克隆仓库

```bash
git clone https://github.com/zcc-01/-.git
cd -
```

> 仓库名就是一个短横线 `-`，所以目录名也是 `-`。如果觉得别扭可以改目录名：
> `git clone https://github.com/zcc-01/-.git agri-trace && cd agri-trace`

### 4. 首次认证

第一次 `git push` 时会弹出窗口要求登录 GitHub，点 **Sign in with your browser**，
在浏览器里授权即可，之后本机会记住凭证，不再重复询问。

如果没弹窗、直接报 `Authentication failed`，说明系统没装凭据管理器，
需要改用 Token 方式（见第五节「常见报错」第 1 条）。

## 三、分支归属（重要：不要都挤在同一个分支）

| 成员 | 固定分支 | 只改这些目录 |
|---|---|---|
| 张××（组长） | `feat/trace-chain` | `app/core/`、`app/db/`、`app/common/`、`app/trace/`、`app/main.py` |
| 李×× | `feat/trade` | `app/trade/`、`app/web/templates/trade/` |
| 王×× | `feat/identity-ops` | `app/account/`、`app/ops/`、`app/web/templates/ops/` |

规则：

- **只在自己的分支上提交**，永远不要直接 push `main`
- **只改自己目录下的文件**。`app/core/`（统一响应、异常、鉴权、主键）是公共契约，
  要改先找组长，否则三人同时改必然冲突
- 需要新增数据库表，在自己的模块里定义 model，然后告知组长在
  `app/models_registry.py` 里注册一次
- 新增前端页面时**继承已有骨架**，不要另起一套 CSS（见第六节）

首次切分支：

```bash
# 组员第一次拿到仓库后，先看有哪些分支
git branch -a

# 切到自己的分支（远程已有就直接跟踪）
git checkout feat/trade          # 李××
git checkout feat/identity-ops   # 王××
```

如果远程还没有自己的分支，从最新的 main 建一个：

```bash
git checkout main
git pull origin main
git checkout -b feat/trade
git push -u origin feat/trade
```

## 四、日常提交（每次改完代码）

```bash
# 1. 提交前先拉一次，避免落后于远程
git pull origin 你的分支名

# 2. 看自己改了什么
git status
git diff

# 3. 加入暂存区（只加自己改的文件，不要 git add . 一把梭）
git add app/trade/
git add tests/test_trade_*.py

# 4. 提交，写清楚做了什么
git commit -m "feat(trade): 商品上架与检索筛选

- ProductService.create 做参数校验与重复上架拦截
- /api/products 支持 keyword/price_min/price_max 组合筛选
- 补 8 个接口测试"

# 5. 推送
git push origin 你的分支名
```

提交信息建议用前缀：`feat:` 新功能、`fix:` 修缺陷、`test:` 补测试、
`docs:` 文档、`chore:` 工程配置。这样 GitHub 上历史清晰，也方便写报告。

## 五、合并到 main（组长操作）

每完成一个可演示的功能，开一次 PR：

1. 打开 https://github.com/zcc-01/-/compare/main...feat/trade
2. 按仓库里的 PR 模板填写：改了什么、怎么验证、影响范围
3. 等 CI 变绿（ruff + pytest + 启动冒烟）
4. **Squash and merge**，删除源分支（可选）

报告表 0-3 需要「合并 PR 数」，因此**不要用本地 merge 后强推 main 的方式**，
必须走 PR，否则 GitHub 不计数。

## 六、前端约定

技术栈是 **Jinja2 服务端渲染 + Bootstrap 5**，没有独立前端工程，
不需要 Node 环境，也不需要 `npm install`。

- 页面放在 `app/web/templates/` 下，按域建子目录：`trade/`、`ops/`
- 新页面**继承** `app/web/templates/base.html`，只填 block，不要复制整页 HTML
- 颜色、间距、卡片样式复用 `app/web/static/style.css` 里已有的 CSS 变量
- 移动端断点统一用 375px 起，扫码页已有范例可参考

新建页面的最小写法（复制即可）：

```jinja
{% extends "base.html" %}

{% block title %}商品详情{% endblock %}

{% block content %}
  <section class="card">
    <h2>{{ product.name }}</h2>
    <p class="muted">￥{{ product.price }}</p>
  </section>
{% endblock %}
```

`base.html` 提供的 block：

| block | 用途 | 是否必填 |
|---|---|---|
| `title` | 浏览器标签页标题 | 建议填 |
| `head_extra` | 追加 `<head>` 内容，如额外 CSS | 否 |
| `subtitle` | 顶部栏副标题 | 否 |
| `alert` | 主体上方告警条（如断链提示） | 否 |
| `content` | 页面主体 | **必填** |
| `footer` | 页脚 | 否 |
| `scripts` | 页面底部脚本 | 否 |

路由里渲染时记得传 `app_name`（骨架的标题默认值依赖它）：

```python
return templates.TemplateResponse(
    request, "trade/detail.html",
    {"product": product, "app_name": settings.app_name},
)
```

## 七、常见报错对照

### 1. `remote: Permission denied` / `403`

原因：没接受邀请，或账号不对。
处理：确认邮件已点 Accept；`git remote -v` 看地址是否正确；
必要时清掉旧凭证重试（Windows：控制面板 → 凭据管理器 → Windows 凭据 →
删除 `git:https://github.com`）。

### 2. `Authentication failed` 且没有弹窗

原因：系统没有凭据管理器，或不支持密码认证（GitHub 早已禁用密码推送）。
处理：用 Personal Access Token 代替密码。

1. 打开 https://github.com/settings/tokens → **Generate new token (classic)**
2. Note 随便填，Expiration 选 30 天，勾选 **repo** 权限
3. 生成后复制 `ghp_` 开头的字符串（**只显示一次**）
4. `git push` 时用户名填 GitHub 用户名，密码位置粘贴这个 token

### 3. `Updates were rejected because the remote contains work`

原因：远程有你本地没有的提交。
处理：`git pull origin 你的分支名`，解决冲突后再 push。
**不要用 `git push -f`**，会覆盖别人的提交。

### 4. `CONFLICT (content): Merge conflict in xxx`

处理：打开冲突文件，搜索 `<<<<<<<`，保留正确内容并删除
`<<<<<<<`、`=======`、`>>>>>>>` 三行标记，然后：

```bash
git add 冲突文件
git commit -m "merge: 解决 xxx 冲突"
git push origin 你的分支名
```

如果冲突文件根本不该由你改（例如 `app/core/` 被别人动了），
停下来在群里说一声，不要硬解。

### 5. `ModuleNotFoundError: No module named 'app'`

原因：命令不在项目根目录执行。
处理：`cd` 到含 `app/` 目录的那一层再运行。

### 6. Windows 上 `python` 打开微软商店

原因：PATH 里只有 `WindowsApps` 的占位符。
处理：用 `py` 命令代替 `python`，或直接双击项目根目录的 `run.bat`。
